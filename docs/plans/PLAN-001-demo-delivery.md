## 1. 交付边界与判定

交付一个可本地运行的中文 Web Demo，五个页面、可重置模拟数据、可重现异常脚本及操作说明。模型提取、OCR、评分依据生成采用确定性场景模拟，评分公式按 PRD 真实计算。页面持续显示简洁的“演示模式 · 合成资料”标识。

本轮仅制定计划。开发进入条件为对象与交互提案中影响当前切片的业务语义已经明确；不要求先完成数据库、HTTP 接口、真实模型服务或部署方案。Demo 通过仅证明交互及状态一致，不证明招聘效果。

验收基线：SPEC 的 D01–D12 均能按脚本重现；主要操作无死按钮；列表、详情、历史三个视图事实一致；工作台与 PDF 阅读清晰；失败后能够继续操作。

## 3. 信息架构及布局

建议桌面优先、浅色首发；1440×900 为主设计视口，同时验收 1280×800、1024×768、390×844。浅色和桌面优先为设计建议，不改变移动端核心流程可达要求。

| 页面 / SPEC ID | 主区域及操作 | 依赖 / 空态 |
|---|---|---|
| 岗位列表 P01 | 岗位名称、标准状态、批次入口；新建岗位 | 无岗位时展示创建引导；不能只显示演示批次而无创建入口 |
| 标准编辑 P02 | 左侧 JD，右侧条件编辑；区分必要条件/加分项、重要性/约束；确认栏 | 岗位和标准草稿；未确认禁止导入，提取失败保留输入 |
| 批次导入 P03 | 岗位/版本摘要、选文件区、逐项校验清单、提交 | 已确认标准；显示选择数量与可提交数量；不伪造上传成功 |
| 批次工作台 P04 | 批次切换、阶段计数、系统队列筛选、人工状态筛选、候选人表格 | 批次及对象快照；默认全部，错误和未配置队列可达 |
| 复核详情 P05 | 左侧原件，右侧分数/覆盖率、条件证据、人工决定；历史选择、补充抽屉 | 评估版本与材料；详情路由独立可访问；返回恢复原筛选 |

桌面详情左右比例约 55:45，证据与 PDF 可独立滚动；固定操作栏不能遮挡最后一项。1024px 以下采用“评估 / 原件”页签，保留选中证据及页码；窄屏表格改为有明确字段标签的条目，系统分组和人工决定均保留。不把整页缩放成桌面截图。

工作台列优先级：候选人、已知条件匹配分、覆盖率/已知数、系统分组、人工决定、处理状态、查看。手机号等非本轮判断必要的信息不进入列表主列。历史标准版本清晰标识；跨版本不可直接混排。

## 4. 视觉与组件基线

先交付 P04 工作台和 P05 详情的高保真静态布局及关键状态，再扩展其他页面。以真实长度的中文合成内容评审，不用 lorem ipsum 验证布局。

| Token 类别 | 初始建议 |
|---|---|
| 背景 / 阅读面 | 页面 #F7F8FA；阅读面 #FFFFFF；正文 #20242C，辅助文字 #566171 |
| 强调色 | #2457D6；状态同时配文字/图标，不仅靠颜色 |
| 字体 | 系统字体 + PingFang SC、Microsoft YaHei；正文 14–16px，标题 24–28px，分数等宽数字 |
| 间距 | 4、8、12、16、24、32px；使用统一 token |
| 圆角 | 控件 10–12px，面板 20px，抽屉 24px，分段控件胶囊；嵌套圆角随内边距调整 |
| 玻璃 | 白色透明度 0.82–0.92，blur 12–20px，saturate 180%；顶部微高光、两层轻阴影 |
| 焦点 | 2px 可见焦点环，与玻璃高光独立，不被 overflow 截断 |

玻璃应用位置：顶部导航、队列分段控件、详情操作浮层。候选人表格行、证据正文和 PDF 不逐个叠加模糊。模糊不支持、降低透明度或手动“减少视觉效果”开启时，切换实色背景；不能只依赖兼容性有限的媒体查询。contain:paint 仅在不会裁剪菜单/阴影/焦点的位置使用。

基础组件：Button、Field、Select、StatusBadge、GlassSurface、QueueFilter、Dialog/Drawer、EmptyState、ErrorState、Skeleton、Toast。业务组件：CriteriaEditor、UploadQueue、BatchProgress、CandidateTable、ScoreSummary、EvidenceList、DocumentViewer、ReviewForm、EvaluationHistory、SupplementDrawer。

每个组件维护 default/hover/focus/disabled/busy/error 等适用状态；用原生语义按钮和表单，不将 div 包装成无键盘行为的控件。主按钮数量受页面任务约束，不能每个面板都使用高饱和主操作。

## 5. 动效规格

| 动作 | 建议表现及预算 | 中断、失败及降级 |
|---|---|---|
| 按钮按压 | scale 0.98，120–160ms；释放恢复 | 禁用态不执行；reduce-motion 时无缩放 |
| 分段控件 | 选中底托位移，220ms | 快速切换跟随最新选择；数据选择立即生效，不等动画完成 |
| 补充抽屉 | 侧滑+淡入，280ms；关闭 220ms | 使用退出完成事件管理卸载；快速开关可中断；不硬编码额外等待 |
| 错误/成功提示 | 淡入 120ms | 错误持久可见；保存失败保留字段；aria-live 播报结果 |
| 路由切换 | 轻淡入 120–180ms | 切换不白屏；聚焦页面标题；返回列表恢复上下文 |
| 骨架及进度 | 固定尺寸骨架；阶段文字明确 | reduce-motion 使用静态骨架；不展示虚假精确百分比 |

仅动画 transform/opacity，不动画 blur、尺寸或表格位置；will-change 仅在过渡需要时开启并清理。动效不能作为业务状态转换的时钟，不用 setTimeout 判定保存成功。避免列表数据更新自动重排正在复核的候选人。

## 6. 前端工程方案

建议在独立 `demo/` 下创建 React + TypeScript + Vite 应用，React Router 管理页面；CSS 变量和模块样式实现视觉；Zustand 保存规范化领域对象，显式事件 reducer 约束转换；Zod 校验模拟结果；Vitest + Testing Library 验证规则和组件；Playwright 验证完整流程。PDF.js 按需加载合成 PDF。依赖具体版本在建项时核实并锁定，本计划不声称已安装或兼容验证。

不增加远程查询缓存库和状态机库，当前没有真实远程服务；复杂度确有必要时再评估。状态机以判别联合类型和转换函数表达，避免大量独立 boolean 组合。弹层可采用成熟可访问性原语，使用前核对许可与兼容性。

建议目录职责：

```text
demo/src/
  app/          路由、页面外壳、全局错误边界
  domain/       对象类型、校验、计分、分组、事件及转换
  store/        规范化对象、selectors、模拟快照持久化
  simulation/   合成数据、事件脚本、失败注入、重置入口
  features/     jobs、criteria、import、screening、review
  components/   通用组件和材质组件
  styles/       tokens、布局、动效和降级规则
  tests/        规则、组件和场景验证
demo/public/fixtures/  合成 PDF，引用页码与内容匹配
```

事实层、表单层、导航层、瞬时状态与派生数据遵循 SPEC。所有页面调用同一组领域动作；模拟服务只产出事件，不直接改组件 state。requestId/runId/itemId 共同约束响应归属；重评和历史决定追加快照，旧请求不能改新结果。保存失败不更新正式决定。

模拟快照带 schemaVersion，浏览器持久化只存合成资料；损坏或版本不兼容时展示可恢复提示，不静默覆盖。用户手选文件默认只在会话预览，刷新需重新选择；不把其内容发送任何服务。处理演示使用预置合成简历，不把预置评价套给任意上传 PDF。对象 URL 在释放预览时撤销。

## 7. 模拟数据与规则隔离

建立一个主岗位、一个第二岗位隔离样例、同岗两版标准、两批合成简历。覆盖至少：证据完整、关键未知、明确冲突、冲突+未知、全未知、扫描升级、解析失败、原件不可用、复核保存失败、补充后重评、旧响应迟到。另有 50/51 项批量边界脚本，不要求制作 51 份不同正文。

合成 PDF 引用必须能定位真实页文；没有坐标只跳页，不能用假高亮冒充精确定位。全部模拟输入与事件固定可复现，不依赖随机失败。

推荐阈值不编造：规则未配置时展示“待配置推荐规则”；推荐队列的视觉样例使用独立、明确标为预置展示的场景，不与计算结果混合。演示控件置于独立场景面板，不占用 HR 正常主流程。

## 10. 验证与交付标准

规则层重点验证缺失分母、权重、冲突优先、版本隔离和迟到响应；组件层验证保存失败保留输入、重复提交、焦点归还和脏表单离开；端到端跑 SPEC D01–D12 并增加同名候选人隔离、跨页面返回、双击操作。

视觉检查在四个指定视口执行，无整页非预期横向溢出、遮挡和截断；200% 缩放仍能访问主要操作。检查正文对比度至少 4.5:1，必要控件/焦点边界至少 3:1；玻璃效果以实际合成背景核验，颜色 token 本身不能证明通过。键盘能完成核心复核，弹层限制焦点且退出归还。

性能以本地生产构建、50 项批次场景实测并记录设备和浏览器；检查切换筛选和打开详情的重复主线程长任务、PDF 懒加载、未清理监听及动画结束后的 will-change。目标是不出现由应用反复触发的超过 50ms 长任务；若未达到，先减弱玻璃层和动画再评估更复杂优化。不得把本地测试称为真实用户 Core Web Vitals 结论。

交付报告记录每条场景通过/失败/未测、截图位置和复现步骤；不把静态设计、模拟数据成功或构建通过当作真实模型效果证明。剩余后续工作包括 API、后端架构、真实文件处理、模型接入、访问和数据治理、独立样本业务验收。
