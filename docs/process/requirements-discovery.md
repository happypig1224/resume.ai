# 需求调研与评审规范

生效日期：2026-10-30。适用范围：本项目后续所有 grill me 需求访谈及其需求文档。规则来源：项目负责人明确要求。

## 1. 访谈前调研

每次 grill me 必须先联网搜索相关业务资料，阅读与本次决策有关的原始来源。优先采用官方产品文档、平台协议、标准机构资料、官方工程指南以及项目源码和维护记录。不得仅凭搜索摘要或模型记忆宣称完成调研。

调研应覆盖目标用户的实际工作流程、相关产品的处理方式、影响方案选择的业务约束。涉及平台规则、个人信息或第三方模型服务时，核对适用地区、版本和发布日期。

## 2. 逐轮提问

每轮只问一个核心问题，提供选项、优缺点及推荐理由。依据已有回答继续追问，不重复确认已经确定的事项。用户指定轮数时遵守轮数；未解决的问题记录为待决事项，不擅自扩展为已确认需求。

外部资料用于解释选项和检验假设，不能替代用户的业务决策。新回答影响既有研究结论时，补充搜索并更新证据。

## 3. 工程实践复核

形成需求文档前，必须再联网检索并复核与范围有关的工程实践，至少检查：

- 异步任务、超时、重试、幂等、部分失败及恢复。
- 数据持久化、版本、来源追溯、访问控制和删除。
- 文件上传校验、第三方服务数据边界及敏感信息日志。
- 涉及模型时的结构化输出、证据核查、提示注入、评估样本和人工复核。
- 指标定义、异常分支及可重复执行的验收方式。

根据当前规模判断适用性，不因大型系统采用某组件就直接引入。每个采纳或不采纳的建议说明理由；不把实践建议写成用户已确认的要求。

## 4. 证据记录

每次访谈建立 `docs/research/RES-<序号>-<主题>.md`，记录检索词、检索日期、来源标题、URL、发布或更新日期（未知则注明）、实际读到的内容、适用范围、影响的决策及未验证事项。结论区分用户确认、来源支持、工程建议和待验证假设。

若联网或审批工具不可用，应记录实际错误和未核验范围，不绕过限制，不编造已读来源。可以继续整理用户输入，但相关结论保留“外部核验未完成”状态，不宣称满足联网调研要求。

## 5. 文档交付

使用正式 PRD 结构：背景、目标、用户、范围、功能需求、业务规则、异常处理、数据要求、验收指标、待决事项及变更记录。需求和验收使用稳定编号。删除对话式措辞、宣传语、未经证实的效果判断及笼统质量形容词。

交付前核对每项用户决定是否保留、指标是否可计算、边界条件是否覆盖、外部事实是否有来源、建议是否被误写成已确认要求。同步更新文档索引。

## 6. AI Native 需求拆解门槛

2026-10-31 补充：高保真 Demo 前先完成对象模型、动作输入输出、页面清单/依赖、组件状态、前端状态转换及状态管理归属。接口协议和后端架构可在 Demo 后补齐，用户可见异常、版本变化与恢复行为必须提前定义。用交互场景验收 Demo，不仅检查页面视觉；模拟状态不得冒充真实服务能力。设计提案与用户确认事项分别标记。

AI Native 开发依赖可检验的输入、显式的规则和边界。PRD 不以篇幅或功能点数量判断完整度；每项进入开发的需求必须有唯一可解释的行为契约，避免让模型、代码生成工具或不同实现者自行补业务语义。

每个可交付需求至少记录：稳定 ID、用户/触发条件、前置条件、输入及来源、主流程、业务规则和优先级、输出及状态变化、失败/不确定/重试行为、数据与版本边界、可观测结果、可重复执行的验收场景。与模型有关的需求还要明确模型职责与程序职责、结构化输出字段和约束、证据来源/引用要求、无效或拒答输出的处理、人工复核点及评估样例。

按三层文档拆解，避免把所有内容塞进 PRD：

- PRD 决定用户价值、范围、业务规则、人工控制点、用户可见状态和验收目标。
- 技术设计决定服务/组件、数据结构、接口、任务状态机、幂等/重试/恢复策略及模型调用契约；不得自行改变 PRD 业务语义。
- 验收规格给出代表性输入、逐步操作、预期状态/结果、边界和失败场景，覆盖主流程及风险最高分支。

开发准入采用需求级判断：未决事项若会改变该需求的分支、持久化语义、人工决策、数据处理或验收结论，该需求不得进入实现；独立且不影响它的需求可以先做。探索性原型可在合成数据和明确标注假设的条件下推进，不得将探索结论误称为已确认需求或生产就绪。

模型输出按非可信输入处理。需求须定义机器可验证的 schema/枚举/范围，以及引用是否能映射回原始材料；验证失败、证据冲突、低置信或超时必须进入明确的拒绝、重试、人工核查或异常状态，不得静默补全。验收应包含正常、边界、对抗输入和失败恢复样例，并单独衡量模型质量及业务结果；自动生成的测试或代码不替代独立验收。

本门槛是项目交付约定，不是外部标准认证。适用的安全、隐私、模型治理及工程约束仍按本规范第 1、3、4 节完成来源核验并记录证据状态。

本规范为后续工作的执行要求；制定本规范本身不代表历史访谈已经完成联网调研或外部实践核验。
