## 1. 项目背景与产品定位

### 1.1 业务痛点与行业现状
在现有的企业招聘场景中，HR 团队与用人部门面临多重严峻挑战：
1. **海量简历初筛成本极高**：在招聘旺季，HR 需在短时间内阅读海量 PDF 简历。人工逐份通读耗时耗力，极易因疲劳导致**漏筛优质人选**，且不同 HR 或不同时段的评估标准难以保持一致。
2. **传统关键词与黑盒 AI 评分的硬伤**：
   - **大模型黑盒打分不可解释**：单纯由大模型直接输出一个 0~100 的综合分，由于存在模型幻觉和随机波动，分数缺乏公信力。
   - **“信息未提及”被直接误判为“不符合”**：传统算法常把简历中未写明的内容（`Unknown`，信息缺失）直接算作能力不足（`Unmet`，明确不符），造成大量冤杀。
   - **缺乏原文溯源与证据链**：多数系统仅提供一两句泛化评语，HR 无法核实真实依据，最终不得不重新通读原件，未能真正解放复核效率。
3. **平台与合规安全边界**：
   - 直接爬取外部招聘平台（如 BOSS 直聘）存在账号被封禁、逆向接口违约等法律与技术风险。
   - 本项目严格立足于企业合法持有、合规导入的简历资产，优先验证“证据抽取 + 确定性评分 + 人机复核”的有效性。

### 1.2 产品定位与核心使命
* **定位**：**“证据驱动 + 人机协同（Human-in-the-Loop, HITL）”智能简历初筛工作台**。
* **第一原则**：**优先减少漏选，其次提升复核效率**。
* **核心铁律**：**严禁算法静默自动淘汰（Zero Auto-Rejection）**。系统负责搜集原文证据、提供判断建议和队列分流，HR 始终保留最终的推进或淘汰决定权。

### 1.3 关键试验目标
- **漏选率控制**：HR 认为值得沟通的人选中，至少 **95%** 准确进入系统的推荐或待核实队列。
- **效率提升**：相较逐份通读原件，整批人工复核总耗时降低至少 **30%**。
- **状态 100% 可追踪**：每份文件处理状态闭环，解析失败进入异常待办，绝不当作低匹配度打分。

## 2. 核心功能体系架构

系统功能围绕 **“岗位标准引擎”**、**“逐级解析与证据检索引擎”** 与 **“确定性评分分流与人机复核引擎”** 三大核心模块构建：

```
┌────────────────────────────────────────────────────────────────────────┐
│                        智能简历筛选助手 (Resume.AI)                       │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
    ┌───────────────────────────────┼───────────────────────────────┐
    ▼                               ▼                               ▼
【1. 岗位标准引擎】              【2. 简历解析与证据引擎】         【3. 评分分流与复核闭环】
· JD 结构化提取                 · 文本/OCR/多模态逐级解析         · 确定性已知条件匹配分
· 约束分级 (不可放宽/可酌情)      · 逐项判定 (Met/Unmet/Unknown)   · 动态证据覆盖率
· 重要性权重 (3:2:1)             · 原文引用与 PDF 页码精确定位     · 三大优先级系统分流队列
· 不可变版本快照 (Versioned)     · 异常待办与单项失败重试          · 左右分屏原件对照复核
                                                                 · 定向补充资料与版本重评
```

### 2.1 FR-01 岗位标准配置引擎 (Criteria Engine)
- **多维结构化 Rubric**：
  - **条件分类**：必要条件（Required）与 加分项（Bonus）；
  - **约束属性**：不可放宽（Strict，底线红线指标）与 可酌情（Flexible，允许相关替代成果）；
  - **重要性权重**：高 (3)、中 (2)、低 (1) 三档固定权重，由重要性自动换算，杜绝自由配置带来的主观失真。
- **不可变版本快照（CriteriaVersion）**：
  - HR 编辑并确认标准后，生成不可变的确定版本快照；
  - 批次导入严格绑定已确认版本，后续修改标准自动生成新草稿，不影响历史批次评估基线。

### 2.2 FR-02 批量导入与任务调度 (Batch Import & Task Queue)
- **批量导入**：支持单批次最多 50 份 PDF 简历导入，绑定当前岗位的有效标准版本；
- **并发与任务隔离**：批次状态由下属筛选项派生；单份文件失败不阻塞批次内其他文件的解析与评估。

### 2.3 FR-03 逐级简历解析引擎 (Tiered Resume Parser)
- **阶梯式容错升级**：
  1. 第一阶段：纯文本提取与结构化（高效、低成本）；
  2. 第二阶段：文本质量不足或格式异常时，自动升级 OCR 识别；
  3. 第三阶段：复杂排版、扫描件升级多模态视觉大模型解析。
- **异常待办保障**：完全无法解析的文件直接进入“异常待办”，提供错误原因与重试机制，绝不伪造低分。

### 2.4 FR-04 证据检索与逐项匹配 (Evidence-Based Finding & Citations)
- **事实与推断分离**：模型针对每项条件只做客观判断：
  - `符合 (Met)`：有明确原文证据支撑；
  - `不符合 (Unmet)`：有明确原文证据证明不满足不可放宽要求；
  - `证据不足 (Unknown)`：简历未提及，明确记录为未知，严禁脑补推断。
- **证据精确定位**：每个 `Met` / `Unmet` 判断必须绑定原件 PDF 页码（Page）与原文逐字引文（Quote），实现精准回溯。

### 2.5 FR-05 确定性评分与分流机制 (Deterministic Scoring & Triaging)
系统严禁大模型直接给出综合分，所有得分与队列归属均由**确定性程序规则**计算：
1. **已知条件匹配分**（0~100）：
   $$\text{已知条件匹配分} = \frac{\sum \text{符合的必要条件权重}}{\sum \text{已知(符合+明确不符合)的必要条件权重}} \times 100$$
   *注：证据不足（Unknown）不计入分母，不因没写而直接扣分；全未知时显示“证据不足，暂不评分”。*
2. **证据覆盖率**（0~100%）：
   $$\text{证据覆盖率} = \frac{\sum \text{已知必要条件权重}}{\sum \text{全部必要条件权重}} \times 100\%$$
3. **加分项独立展示**：加分项不并入主匹配分，单独展示满足项及依据，避免弱化必要条件。
4. **三大优先级系统分流队列**：
   - **优先级 1 · 条件冲突队列 (Conflict)**：任一不可放宽必要条件（Strict）明确不符合 (`Unmet`)，系统优先拦截；
   - **优先级 2 · 待核实队列 (Verification)**：无明确硬伤冲突，但关键条件（所有 Strict 条件 + High 重要性 Flexible 条件）存在证据不足 (`Unknown`)，提示 HR 电话追问；
   - **优先级 3 · 推荐候选人队列 (Recommended)**：关键条件齐全，且匹配分与覆盖率均达到岗位校准门槛；
   - **其他/待配置队列**：规则未校准或低分人选，保留全量访问，不予静默淘汰。

### 2.6 FR-06 人机协同复核与追溯 (HITL & Audit Trail)
- **左右对照工作台**：左侧显示原始 PDF 文件（支持页码跳转与引用定位），右侧展示评分卡、证据链与人工决策面板；
- **决策留痕**：HR 做出 `推进沟通`、`待补充信息`、`暂不推进` 决策，打上快捷标签（如“年限不足”、“行业背景极契合”）并填写备注；
- **版本历史**：所有复核操作追加留痕，可追溯历次决定。

### 2.7 FR-07 定向补充资料与增量重评 (Targeted Re-Evaluation)
- **防反向注入机制**：HR 针对待核实项通过电话追问获取信息后，录入定向补充说明（需显式指定补充针对的具体条件与裁定结果），杜绝“一段文本全量洗白”的漏洞；
- **快照独立**：每次重评生成全新的评估快照（Evaluation Snapshot），旧版快照与旧版人工决定完整保留，并提示 HR 二次确认。

### 2.8 FR-08 异常恢复与稳态保障 (Fault Tolerance)
- 刷新或网络中断后，已完成评估完整恢复；
- 提供单项失败重试、并发提交互斥拦截。

## 3. 完整业务闭环全景流程

从岗位定义到最终录用决策，系统形成高度自洽的端到端人机协同闭环：

```mermaid
flowchart TD
    %% 阶段一：标准准备
    subgraph S1["阶段一：岗位与标准定义"]
        A[输入/粘贴 岗位 JD] --> B[AI 辅助解析与条件拆解]
        B --> C[HR 编辑/校对标准<br/>设定必要/加分、不可放宽/权重]
        C --> D[确认并冻结标准版本快照<br/>CriteriaVersion]
    end

    %% 阶段二：数据输入与解析
    subgraph S2["阶段二：批量导入与任务执行"]
        D --> E[选择岗位与已确认版本]
        E --> F[批量上传 PDF 简历<br/>≤ 50 份/批，格式校验]
        F --> G[创建批次任务 Batch]
        G --> H[逐级解析: 纯文本 → OCR → 多模态]
        H -- 解析失败 --> H1[进入【异常待办】<br/>支持单项重试，不扣分]
    end

    %% 阶段三：证据抽取与确定性计算
    subgraph S3["阶段三：证据检索与规则分流"]
        H -- 解析成功 --> I[逐项条件证据检索<br/>锁定引文 Quote 与 PDF 页码]
        I --> J[输出判定: Met / Unmet / Unknown]
        J --> K[程序计算匹配分与证据覆盖率<br/>加分项独立展示]
        K --> L{优先级自动分流}
        L -- 任一不可放宽条件 Unmet --> M1[【条件冲突队列】<br/>硬性条件不满足]
        L -- 无冲突但关键条件 Unknown --> M2[【待核实队列】<br/>关键信息缺失待追问]
        L -- 关键条件齐全且达标 --> M3[【推荐候选人队列】<br/>高匹配优先沟通]
        L -- 未达标或待校准 --> M4[【其他候选人】<br/>全量留存不淘汰]
    end

    %% 阶段四：人机协同复核与闭环
    subgraph S4["阶段四：人机协同复核与数据演进 (HITL)"]
        M1 & M2 & M3 & M4 --> N[HR 进入批次工作台]
        N --> O[打开候选人详情页<br/>左侧原件 PDF vs 右侧证据评分]
        O --> P{HR 做出人工决策}
        P -- 认可匹配 --> Q1[决策: 推进沟通]
        P -- 存在硬伤/不合适 --> Q2[决策: 暂不推进 (保留原因)]
        P -- 信息不全需核实 --> Q3[决策: 待补充信息]
        
        Q3 --> R[电话沟通/收集补充材料]
        R --> S[录入定向补充说明<br/>Targeted Supplement]
        S --> T[触发系统增量重评<br/>生成新评估快照 Evaluation]
        T --> K
    end
```

### 业务流转各阶段详述：

1. **阶段一 · 岗位与标准定义（标准基线）**：
   - HR 在系统内创建岗位并粘贴 JD，AI 提取候选条件；
   - HR 在界面上进行微调：确定必要条件（不可放宽 vs 可酌情）与加分项，配置高/中/低重要性；
   - 点击“确认”，系统生成唯一的、不可变的 `CriteriaVersion` 版本快照。
2. **阶段二 · 批量导入与任务执行（数据受理）**：
   - HR 选定岗位及标准版本，拖拽上传一批 PDF 简历（≤50 份）；
   - 系统执行格式检查，创建批次对象及各筛选项对象；
   - 后台调度器执行逐级解析流水线（文本提取 → 质量校验 → 必要时升级 OCR/多模态），若解析失败则归入异常待办，可一键重试。
3. **阶段三 · 证据抽取与确定性计算（算法执行）**：
   - 对成功解析的简历，按岗位标准逐条检索上下文证据；
   - 输出结构化判定：`Met`（附原文与页码）、`Unmet`（附冲突依据与页码）、`Unknown`（无提及）；
   - 确定性评分函数依据 3:2:1 权重计算已知条件匹配分与覆盖率。
4. **阶段四 · 优先级规则自动分流（漏斗分类）**：
   - 算法依据三层优先级将人选分流到不同工作队列：
     - 不可放宽不符 $\rightarrow$ **条件冲突队列**；
     - 关键条件缺失 $\rightarrow$ **待核实队列**；
     - 达标人选 $\rightarrow$ **推荐候选人队列**；
     - 其余人选 $\rightarrow$ **其他候选人**。
5. **阶段五 · 人机深度复核（HITL 落地）**：
   - HR 进入工作台，根据系统分流列表按优先级开展审阅；
   - 在复核详情中，点击具体条件判定即可联动高亮原件对应页与引文，免去人眼通读定位的耗时；
   - HR 审阅后提交人工决定（推进沟通 / 暂不推进 / 待补充信息），系统留存审计记录。
6. **阶段六 · 定向补充重评与演进（闭环驱动）**：
   - 对“待补充信息”的人选，HR 通过电话沟通核实细节后，使用抽屉录入定向补充材料；
   - 系统生成新的评估快照版本，自动重评并更新分流状态，HR 进行最终确认，完成整个闭环。

## 4. 与传统方案的核心差异与防腐设计

| 维度 | 传统简易 AI / 关键词方案 | 本项目设计方案 | 核心业务价值 |
| :--- | :--- | :--- | :--- |
| **打分逻辑** | 大模型直接输出综合分（随机性大、黑盒） | 确定性程序公式计算（Met/Unmet 严格依权重计算） | 杜绝大模型算分幻觉，评分具备完全透明性与稳定性 |
| **信息缺失处理** | 没写的条件直接算 0 分或判淘汰 | 标记为 `Unknown`，扣除覆盖率，归入**待核实队列** | 保护排版简短或遗漏关键字的优质候选人，杜绝误杀 |
| **淘汰决策权** | 算法低分直接自动拦截、拒信通知 | **零自动淘汰**，系统仅提供分流建议，HR 保留终审权 | 彻底规避法律与平台合规风险，保护候选人与企业权益 |
| **证据可信度** | 泛化的文字描述，无法查验出处 | **每项条件强制绑定 PDF 页码与原文高亮引用** | 点击直达原件出处，HR 复核效率提升 30% 以上 |
| **标准追溯性** | 修改 JD 全局受影响，历史批次结果失真 | **版本化不可变快照（Confirmed CriteriaVersion）** | 评估结果与判定版本永久绑定，支持回溯与审计对比 |
